# VibeKit Global & Project Rules (Legacy Bridge)
# Canonical rules live in core/RULES.md, core/WORKFLOW.md, core/UI_UX_PREFERENCES.md, and AGENTS.md.

1. **Quality First, Adaptive Execution (`AUTO` mode)**: Prioritize security and data integrity, complete working functionality (zero dead buttons or fake handlers), the owner's mandatory UI/UX standard (`UI-UX Preferences.txt` & `core/UI_UX_PREFERENCES.md`, ignored ONLY when the PRD explicitly mentions a simplistic UI/UX), maintainable engineering, and real verification.
2. **Model-Agnostic & Agent-Portable**: Never lock work to a specific model (`model: inherit`) or platform-only tool. Use Orchestrator (Argon) or subagents natively when available; execute sequentially in `SOLO` mode otherwise.
3. **Flexible PRD & Auto-Setup**: Read `PRD.md`, `PRD.txt`, or any clearly identifiable PRD file. If VibeKit files are missing from a project folder, install them automatically via `~/.vibekit/kit-path.txt` without asking the owner to run manual setup commands.
4. **Preserve Working Code & Stack Independence**: Detect the actual stack (`package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `pubspec.yaml`, etc.) before running commands—never blindly assume `npm run dev`. Keep working code intact on feature additions and `DEBUG ONLY — STRICT BUG FIX` (no unrequested redesigns or PRD edits); when debugging with a strong agent (`DEBUG & OVERHAUL EXISTING PROJECT`) or redesigning (`IMPROVE UI/UX`), freely overhaul weak code, motion, UI/UX, and strategic PRD details while preserving core purpose and working features.
5. **UI/UX Ambition & Proportions (`UI-UX Preferences.txt` & `core/UI_UX_PREFERENCES.md`)**: Always apply the owner's full UI/UX preferences and standard (artistic flagship feel at `CodeSense (pr-reviewer)` / `Haan` ambition level, rich density with zero empty hero/section voids, bold scroll/interactive motion, immediate discoverability, convincing real 3D like `TicketRaja` when 3D is part of the promise, `BookMyShow`-grade mobile polish, crisp `1440px–1920px` desktop proportions, and zero visual defects)—ignored ONLY when the PRD explicitly mentions a simplistic UI/UX.
6. **Build -> Review/Revise -> Deploy Boundary**: Stop at a verified local preview (`READY FOR MY REVIEW`) by default and ask for owner feedback. Never deploy, publish, or push to a production-triggering branch unless `DEPLOY MY PROJECT` (or explicit deployment authorization in the current session) is given, which runs full Stage 6 readiness + Stage 7 deployment together.
7. **Secrets & Account Boundaries**: Keep `.env*` secrets out of chat and git. Ask at most one unavoidable external owner step at a time. Never pause/delete existing cloud projects or mix personal accounts into friend/client projects.
